# 2026 SCUT 集成电路专业工程创新训练

## 循迹避障智能小车

本项目是 **2026 年华南理工大学（SCUT）集成电路专业工程创新训练课**的循迹避障小车项目。小车以 STM32F103C8T6 为主控，使用 8 路灰度传感器识别赛道黑线，使用左右两路 HC-SR04 超声波检测前方障碍物，并通过双路编码器和 PID 控制实现稳定的闭环行驶。

项目重点不只是让小车“能跑”，而是将传感器采集、实时控制、执行器驱动、状态机和调试显示整合在一个完整的嵌入式系统中：

- **循迹**：根据 8 路灰度传感器的黑线分布计算偏差，位置环 PID 生成转向修正；
- **避障**：根据左右超声波距离触发绕行状态机，绕过障碍后重新捕获赛道；
- **速度闭环**：编码器测量左右轮实际速度，左右轮分别使用速度 PID；
- **交互与调试**：蓝牙控制启动/停车，OLED 显示电机 PWM、轮速、灰度编码和超声波距离；
- **安全停车**：支持蓝牙停车、终点线停车，以及异常状态下的电机制动。

> 当前仓库包含完整的 STM32CubeMX/CMake 工程和 BSP 驱动代码。硬件安装、传感器阈值、PID 参数以及避障距离需要结合实际小车底盘和赛道进行标定。

## 1. 系统方案

### 1.1 总体架构

```text
                 ┌──────────────────────────────┐
                 │         STM32F103C8T6         │
                 │                              │
  8 路灰度 ────> │ 循迹位置计算 ─> 位置 PID      │
  左右超声波 ──> │ 避障状态机                    │
  左右编码器 ──> │ 速度测量 ───> 左/右速度 PID  │
                 │                              │
  蓝牙串口 ────> │ 运行状态与命令管理            │
  OLED 软件 I2C  │ 调试信息显示                  │
                 └──────────────┬───────────────┘
                                │
                         PWM + 方向控制
                                │
                         双路直流减速电机
```

### 1.2 硬件选型

| 模块 | 选型/实现 | 作用 |
| --- | --- | --- |
| 主控 MCU | STM32F103C8T6 | 运行实时控制逻辑和外设驱动 |
| 灰度传感器 | 8 路数字灰度传感器 | 检测黑线位置、丢线和终点线 |
| 电机 | 左右两路直流减速电机 | 差速驱动小车 |
| 电机驱动 | 双路 H 桥驱动，PWM 调速、GPIO 控向 | 驱动电机正反转、滑行和刹车 |
| 编码器 | 双路正交编码器 | 测量左右轮速度和累计位移 |
| 测距 | 2 个 HC-SR04 | 检测左、右侧障碍物距离 |
| 通信 | BT-24 蓝牙串口模块 | 手机发送启动、停车命令 |
| 显示 | SSD1306 OLED，软件 I2C | 显示控制量和传感器状态 |
| 指示 | PC13 LED | 指示运行状态 |

主控系统时钟配置为 **72 MHz**。TIM1 以 **10 ms** 为控制周期；TIM2 输出电机 PWM。编码器使用定时器的正交编码器模式，编码器参数在 [`BSP/Inc/encoder.h`](BSP/Inc/encoder.h) 中定义为 13 线、1:20 减速、4 倍频，即输出轴每转 1040 个计数。

## 2. 软件控制逻辑

### 2.1 主循环与 10 ms 控制中断

系统初始化后，主循环主要负责：

1. 调度非阻塞超声波测距状态机；
2. 读取蓝牙环形缓冲区并处理 `start`/`stop` 命令；
3. 获取左右超声波状态，并在允许避障时交给避障模块；
4. 每 200 ms 更新 OLED 调试信息。

TIM1 每 10 ms 进入一次控制中断，执行实时控制：

1. 读取左右编码器速度；
2. 处理启动/停车请求；
3. 读取 8 路灰度传感器；
4. 执行终点检测和避障状态机；
5. 计算目标轮速；
6. 运行左右轮速度 PID；
7. 将 PID 输出转换为 PWM 和电机方向。

这种划分避免了在实时控制中断中执行蓝牙解析、OLED 刷屏或超声波长时间等待，使控制周期保持稳定。

### 2.2 循迹算法

8 路灰度传感器被压缩为一个 8-bit bitmap。每一路检测到黑线时，对应 bit 置 1。软件为 8 个探头分配从左到右的非等距权重：

```text
[-5, -4, -2, -1, 1, 2, 4, 5]
```

位置误差由黑线探头的加权平均值得到，并归一化到约 `-1000 ~ +1000`：

```text
line_position = Σ(weight[i]) / 黑线探头数量
```

黑线偏左时误差为负，偏右时误差为正。位置 PID 以目标位置 0 为中心，输出转向量 `steer`：

```text
left_target_speed  = base_speed + steer
right_target_speed = base_speed - steer
```

当 bitmap 为 0 时，系统将其视为丢线，而不是把它误认为“车辆正好居中”；此时会复位位置 PID，避免积分项在丢线期间继续累积。

### 2.3 双环 PID

本项目采用“位置环 + 速度环”的双环控制结构：

- **位置环**：灰度位置误差 → 转向修正；
- **速度环**：目标轮速与编码器实际轮速 → 左右电机 PWM。

当前 `main.c` 中的默认参数为：

| 控制器 | `Kp` | `Ki` | `Kd` | 输出范围 |
| --- | ---: | ---: | ---: | ---: |
| 循迹位置 PID | 0.05 | 0.5 | 0 | -40 ~ 40 |
| 左轮速度 PID | 3.0 | 5.0 | 0 | -75 ~ 75 |
| 右轮速度 PID | 3.0 | 5.0 | 0 | -75 ~ 75 |

这些参数是当前程序的起始配置，并不保证适用于所有车体。调参时建议先单独校准速度环，再逐步增加位置环比例和积分作用；电机机械差异较大时，应分别调整左右速度 PID。

### 2.4 避障状态机

避障模块不直接“阻塞转弯”，而是通过状态机在多个 10 ms 控制周期内逐步完成绕行：

```text
IDLE
  │ 左/右距离达到触发条件
  ▼
TURN_OUT          向障碍物相反方向驶出
  ▼
TURN_IN           转入并持续扫描灰度线
  ▼
EXTRA_TURN        捕获中间灰度探头后完成小弧线
  ▼
REJOIN_CONFIRM    确认重新稳定压线
  ▼
IDLE              交回正常循迹
```

软件只使用左右两路超声波参与避障，按 `LEFT -> RIGHT` 顺序轮流触发，避免两个 40 kHz 模块同时工作造成串扰。测距驱动使用 EXTI 捕获 ECHO 边沿和 DWT 计时，不在主循环中使用长延时；连续无回波或超量程时会将该路数据标记为无效。

默认关键参数包括：

- 左右侧距离触发阈值：280 mm；
- 释放距离附加量：60 mm；
- 超声波数据最大有效年龄：300 ms；
- 避障完成后的重新触发冷却时间：1000 ms；
- 转入阶段最短等待：400 ms；
- 重新并线后稳定确认：200 ms。

参数和状态定义集中在 [`BSP/Inc/avoidance.h`](BSP/Inc/avoidance.h)，便于根据车速、轴距和场地宽度调整。

### 2.5 启动、停车与终点检测

当前版本代码在小车启动后前 **7 秒** 暂停避障，只执行循迹，直接通过前两个障碍物（障碍物距离较远不需要避障）。之后才允许超声波触发绕行。

默认蓝牙启动流程如下：

1. 上电后处于停止状态，电机刹车；
2. 手机通过蓝牙发送 `start`、`go`、`s` 或 `1`；
3. 系统读取一次最新灰度和超声波数据，复位 PID 和避障状态；
4. 进入运行状态，LED 点亮；
5. 发送 `stop`、`p` 或 `0` 时立即停车并刹车。

终点检测采用“全黑 + 运行时间门槛 + 重新武装”的组合条件：

- 发车后至少运行 12 秒；
- 灰度 8 路全部检测到黑线；
- 车辆此前已经离开过全黑区域。

这样可以避免车辆停在起点线或障碍物旁的深色区域时被误判为终点。终点停车后，超声波仍继续测距，便于观察车辆周围环境。

## 3. 主要接口与引脚

### 3.1 电机与编码器

| 功能 | 引脚/定时器 |
| --- | --- |
| 左电机 PWM | PA0 / TIM2 CH1 |
| 右电机 PWM | PA1 / TIM2 CH2 |
| 左电机方向 | PB10、PB11 |
| 右电机方向 | PB0、PB1 |
| 左轮编码器 | PB6、PB7 / TIM4 |
| 右轮编码器 | PA6、PA7 / TIM3 |

### 3.2 超声波

| 逻辑位置 | TRIG | ECHO |
| --- | --- | --- |
| 左侧 | PA4（TRIG3） | PA5（ECHO3） |
| 右侧 | PA8（TRIG1） | PA9（ECHO1） |

当前软件不采样原先预留的中间超声波通道 PA10/PA11。超声波模块与 MCU 必须共地；若 ECHO 输出为 5 V，应根据模块和 MCU 的电平容限增加电平转换。

### 3.3 通信与显示

| 功能 | 接口 |
| --- | --- |
| 蓝牙 TXD → MCU RX | PA3 / USART2_RX |
| 蓝牙 RXD ← MCU TX | PA2 / USART2_TX |
| 蓝牙串口参数 | 9600 baud，8-N-1，无硬件流控 |
| OLED SCL | PA12 |
| OLED SDA | PB5 |
| 状态 LED | PC13 |

蓝牙接收采用中断接收和环形缓冲，主循环负责取出完整命令。详细接线和调试方法见 [`BSP/README_bluetooth.md`](BSP/README_bluetooth.md)；超声波采样说明见 [`BSP/README_ultrasonic.md`](BSP/README_ultrasonic.md)。

## 4. 项目结构

```text
.
├── Core/                       # CubeMX 生成的 HAL、外设初始化和主程序
│   ├── Inc/
│   └── Src/
├── BSP/
│   ├── Inc/                    # 传感器、电机、PID、显示等模块接口
│   ├── Src/                    # 各模块实现
│   ├── README_bluetooth.md     # 蓝牙接线与命令说明
│   └── README_ultrasonic.md    # 超声波接线与采样说明
├── Drivers/                    # CMSIS 和 STM32F1 HAL 驱动
├── cmake/                      # STM32 工具链和 CubeMX 子工程配置
├── eit.ioc                     # STM32CubeMX 工程配置
├── CMakeLists.txt              # 顶层 CMake 构建文件
└── CMakePresets.json           # CMake 预设
```

重要代码入口：

- [`Core/Src/main.c`](Core/Src/main.c)：系统初始化、主循环、10 ms 控制中断和整车状态；
- [`BSP/Src/tracking.c`](BSP/Src/tracking.c)：灰度 bitmap 到位置误差的转换；
- [`BSP/Src/avoidance.c`](BSP/Src/avoidance.c)：避障状态机和绕行控制；
- [`BSP/Src/pid.c`](BSP/Src/pid.c)：通用 PID 控制器；
- [`BSP/Src/ultrasonic.c`](BSP/Src/ultrasonic.c)：非阻塞超声波测距；
- [`BSP/Src/motor.c`](BSP/Src/motor.c)：电机方向、PWM、滑行和刹车控制。

## 5. 说明

本项目用于课程实验、嵌入式控制学习和工程实践。代码中的默认参数依赖当前小车的电机、轮胎、供电和赛道条件；更换硬件后应重新进行方向、量程、速度和 PID 标定。
