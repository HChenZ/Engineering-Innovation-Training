# 蓝牙启动控制（USART2 @ 9600）

上电默认待机，用ASCII字符完成 **`1`学习 → `2`停车保存 → `3`比赛** 三个阶段，`0`停车取消。
**注意：`1`不再表示启动比赛。** 地图使用与标定详见 [README_odometry.md](README_odometry.md)。

## 一、硬件接线

| 蓝牙模块 | STM32 | 说明 |
| --- | --- | --- |
| TXD | **PA3**（USART2_RX） | 模块发 → 单片机收 |
| RXD | **PA2**（USART2_TX） | 单片机发 → 模块收 |
| VCC | 5V | HC-05/06 的底板自带稳压；**裸模块只能接 3.3V** |
| GND | GND | 必须共地 |
| EN/KEY | 悬空 | 不接就是正常透传模式 |

串口参数：**9600，8 位数据，无校验，1 位停止位（8-N-1）**，
无硬件流控，所以只要 TX/RX/GND 三根线。

> 模块出厂波特率一般就是 9600（HC-05 可能是 9600 或 38400）。
> 如果连不上，先把模块插到 USB-TTL 上用 AT 指令 `AT+UART?` 查一下，
> 改成 9600 最简单——单片机侧改波特率要动 `usart.c`，不如改模块。

## 二、命令

手机装任意"蓝牙串口助手"（如 蓝牙调试助手 / Serial Bluetooth Terminal），
连上模块后发下面的命令。**大小写都行，结尾带不带 `\r\n` 都行**
数字命令单字节立即解析，不用换行；文字命令使用换行或30ms静默判行。
选择ASCII/文本发送：字符`1`对应HEX `31`，不是二进制 `01`。

| 发出去的内容 | 作用 |
| --- | --- |
| `1` / `teach` / `t` | 学习：只循迹、不避障，暂存RAM；有参考圈长才自动终点停，无参考时发2结束 |
| `2` / `save` | 停车并保存地图，等待`OK MAP ...`；至少学习100cm |
| `3` / `start` / `s` | 有地图才启动比赛：循迹+避障，地图仅作为丢线兜底 |
| `0` / `stop` / `p` | 停车；取消未保存学习和排队保存，不覆盖旧图。数字0有接收回调快速急停路径 |
| `map` / `m` | 查询地图点数、模式和救援状态 |

每收到一条命令，单片机会回一行应答，方便确认链路通：

```
收到 1        ->  OK TEACH
首次无图无圈长 ->  OK TEACH MANUAL END SEND 2（完整跑完时主动发2，不等丢线停车）
学到终点      ->  TEACH READY SEND 2 TO SAVE
收到 2        ->  OK STOPPING TO SAVE，随后 OK MAP <点数> STEP <间隔>
收到 3/start  ->  OK START MAP（无图则 ERR NO MAP SEND 1 TO TEACH）
收到 stop     ->  OK STOP
当前不能切换   ->  ERR BUSY 或 SAVE/ABORT提示
不认识的命令   ->  ERR
```

ASCII `0`的制动不等主循环解析或OLED刷新，收到字节后的下一次10ms控制中断优先执行；急停后旧队列清空，重新发新命令。
ASCII `2`在学习中同样先由控制中断停车，再由主循环保存。文字别名需主循环解析，响应时序不完全相同。
这不包含蓝牙传输延迟，也不保证车轮10ms内机械静止。地图终点进度、回线验证及`END REJ`诊断见`README_odometry.md`。

## 三、车上的状态指示

OLED 每 200ms 刷新一次，四行内容：

| 位置 | 内容 | 例子 |
| --- | --- | --- |
| 页 0 | 状态 | `STOP`（待机/已停车）、`RUN`（运行中）、`FINISH`（终点停车） |
| 页 2 | 最近一条蓝牙命令 | `WAIT CMD` / `CMD:START` / `CMD:STOP` |
| 页 4 | 车头**左侧** U4 距离 | `L 123cm`；无回波显示 `--` |
| 页 6 | 车头**右侧** U1 距离 | `R  87cm`；无回波显示 `--` |

LED（PC13）：亮 = 运行中；灭 = 待机、蓝牙停车、终点停车。

**8 路循迹全部压线（终点线）会触发终止停车**：LED 灭、OLED 状态行变 `FINISH`、车停下。
停车后超声波**保持测距**（只测距，不下发任何动作，电机完全不动），
OLED 上的两路距离继续实时刷新，发车前就能看清左右空间。
想再跑一轮，先回到和示教相同的起点、朝向，再发`3`/`start`；启动会清零地图位姿，**不支持原地断点续跑**。

因为停车期间距离一直在测，发 `start` 时第一次避障判断用的就是**当前**距离：
如果车头 25cm 内已经有障碍物，车会先刹车或者原地绕行，而不是先往前冲一段。

## 四、代码放在哪

| 文件 | 内容 |
| --- | --- |
| `Core/Src/usart.c`、`Core/Inc/usart.h` | USART2 初始化（9600，PA2/PA3），CubeMX 风格 |
| `BSP/Src/bluetooth.c`、`BSP/Inc/bluetooth.h` | 中断接收、命令解析、应答、错误恢复 |
| `Core/Src/stm32f1xx_it.c` | `USART2_IRQHandler` → `HAL_UART_IRQHandler(&huart2)` |
| `Core/Src/main.c` | 主循环里处理 `start`/`stop`（`g_run` 控制跑/停）、OLED 状态与距离显示、终点线锁存 |

接收方式：**单字节中断接收 + 64 字节环形缓冲**，
主循环 `Bluetooth_GetCommand()` 取命令，不会因为主循环忙（OLED、测距）而丢字节。

## 五、和 CubeMX 的关系（重要）

`.ioc` 里已经加好了 USART2（异步、9600、PA2/PA3），重新生成代码不会丢配置。
但有两个地方**故意没用 CubeMX 的 NVIC 勾选**：

* USART2 的**中断使能**写在 `BSP/Src/bluetooth.c` 的 `Bluetooth_Init()` 里，
  优先级 2（低于 TIM1 的 1，保证 10ms 循迹周期优先）。
  这样 CubeMX 重新生成代码不会把它覆盖掉。
* 如果你以后在 CubeMX 里勾上了 "USART2 global interrupt"，重新生成后
  `stm32f1xx_it.c` 里会多出一个 `USART2_IRQHandler`，
  和手写的那份**重定义冲突**（编译报错）——把 `USER CODE BEGIN 1` 里手写的那份删掉即可。

另外 `stm32f1xx_hal_uart.c/.h`（HAL 驱动）和 `stm32f1xx_hal_conf.h` 里的
`HAL_UART_MODULE_ENABLED`、`cmake/stm32cubemx/CMakeLists.txt` 里的源文件列表
都已一并加好，CubeMX 重新生成时会保持一致。

## 六、第一次上电怎么试（建议按顺序）

1. 先不装车（或者把驱动轮架空），上电：OLED 显示 `STOP / WAIT CMD`，电机不动。
2. 手机连上模块，发`1`，应收到`OK TEACH`；它是学习而不是比赛。查TX/RX是否交叉、波特率是否9600、模块是否已配对。
3. 发 `0`，应收到 `OK STOP`，电机刹车。
4. 放回固定起点，移走障碍，发`1`学习完整赛道，到终点停车后发`2`存图。
5. 等`OK MAP ...`，放回同一起点、同一朝向，放上障碍后发`3`比赛。

## 七、如果比赛要求"全自动运行"

本项目自己的避障规则笔记里写着"**非全自动运行直接不予参赛**"，
所以主循环顶部留了一个开关（`Core/Src/main.c` 的 `BT_START_GATE`）：

* `BT_START_GATE = 1`（默认）：上电待机，**必须**收到蓝牙 `start` 才跑，方便调试和发车；
* `BT_START_GATE = 0`：上电**直接开跑**，蓝牙只当紧急停车用，避免被裁判认为"遥控发车"。

比赛当天的发车方式按裁判口径选一个即可，改一个数字、重新编译就行。
