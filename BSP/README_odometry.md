# 二维地图、回线验真与终点进度约束

## 不加按钮、不重烧的使用流程

当前分支已经通过蓝牙接收 `start` / `stop`，地图沿用同一通道。

采用三个独立阶段，由蓝牙ASCII命令明确切换：

| 发字符 | HEX字节 | 阶段 | 行为 |
|---|---|---|---|
| `1` | `31` | 学习 | 从固定起点启动，只循迹不避障，地图暂存RAM |
| `2` | `32` | 停车存图 | 停车后等待150ms，在主循环写Flash，回复`OK MAP ...` |
| `3` | `33` | 比赛 | 必须已有Flash地图，从同一起点发车；无图拒绝启动 |
| `0` | `30` | 紧急停车/取消 | 取消未保存学习及排队保存，不覆盖原地图 |

数字命令单字节立即解析，不需要换行。手机APP选“文本/ASCII发送”，按键内容填`1`而不是`0x01`。
如果APP只能HEX发送，填`31`，不要填`01`。依次完成阶段后再发下一条，不能一次发`123`代替三个物理阶段。

1. 先移走障碍物，观察第一趟是否真的沿黑线而非字体行驶，将车放在固定起点、固定朝向，发`1`学习。
2. **首次无图且未配置圈长**：回复`OK TEACH MANUAL END SEND 2`。无法区分“中途黑字”和“真正终点”，不再凭一块全黑自动结束。请在完整跑完、尚未持续丢线300ms之前主动发`2`停车保存，不能等LOST_LINE作废后再保存。
3. **有旧地图或已填圈长**：学习沿用旧图总长，或使用`teach_finish.h`中的`TEACH_FINISH_EXPECTED_CM`。只在预期终点前后30cm内，且有正常窄线历史、两轮前进时，才接受一帧全黑终点；到终点只停车，回`TEACH FINISH ...`及`TEACH READY SEND 2 TO SAVE`，再发`2`保存。
4. 数字`2`收到后由下一次TIM1优先停车，停车后等待150ms才在主循环写Flash；过短/无效数据仍不保存。文字别名`save`仍需主循环解析，不具备数字单字节快速路径。
5. 收到`OK MAP ...`才算保存成功。等待期间不移动小车，不断电。保存失败会回复错误并保留旧地图。
6. 将车重新放回**同一个起点、同一个朝向**，放置比赛障碍物，发`3`比赛，回复`OK START MAP`。
7. 重学前先停车并取消旧的RAM缓存（`0`），然后回起点发`1`。未保存时直接发`3`会拒绝，防止误用旧图。

保留文字别名：`teach/t`=`1`，`save`=`2`，`start/s`=`3`，`stop/p`=`0`。
`map/m`查询地图模式、点数和救援状态。运行中不能直接切到另一种运行模式，先`0`停车。

不需要增加实体按钮，也不需要每次修改编译宏。每次比赛不会更新地图，避免把避障路径记成黑线。
如果没有可用的蓝牙连接，本分支本身的启动操作也需要另行设计，不能把“没有按钮”理解为能自动区分学习和比赛。

**首次升级二维地图版需要重新学习**：原来只有航向的ODM2地图不兼容新二维ODM3格式。
本次三阶段协议不改变ODM3存图格式，已经存好的二维图仍可加载。`1`的旧“启动比赛”含义已改为“学习”，请同步修改APP按键！

## 记录的内容

- 左右编码器每10ms计算轮轴中心 `(x,y,theta)`，中点法积分。
- 示教每5cm保存传感器前伸位置的 `(x,y)` 和行进方向。它是黑线的**近似中心线**，不是实测绝对坐标。
- 最多250点，约12.45m；容量或坐标范围超限时学习作废停车，不默默稀释地图。
- 学习连续丢线300ms也作废停车。短时间脱线、循迹摆动仍可能影响地图质量。
- **保护停车不再自动丢弃RAM**，仍保留学习模式。发`m`或`2`可看到具体原因：
  - `TEACH FAIL LOST_LINE N... K... GS00`：连续丢线300ms。
  - `TEACH FAIL MAP_FULL N250 K...`：250点用满，学习距离约12.5m。
  - `TEACH FAIL COORD_RANGE ...`：估计坐标超出存储范围。
  - `N`是点数，`K`是估计里程cm，`GS`是停车时的灰度位图（十六进制）。
  故障后发`2`仍拒绝保存，但会返回上述原因，而不是笼统的`NO TEACH DATA`。
  无效地图不能强制当完整赛道使用；检查对应原因，发`0`取消、回起点发`1`重新学习。
  正常终点停车显示`TEACH READY SEND 2 TO SAVE`，不是`TEACH FAIL`。
- 丢线故障还会输出最多4行`GS ...`，每两个HEX字符是一帧位图，每帧10ms；按时间从旧到新给出最近640ms，便于判断经过终点时是否实际读到FF。
- 当前假定**终点是横跨8路探头的黑色横线**。如果物理终点只是黑线消失、横线未覆盖全部探头，或者整条横线都处在两个采样之间，则这条终点识别仍不成立，不能将任意白区当终点。需要检查终点样式/宽度，或跑完整圈时主动发`2`结束学习。
  单帧全黑在交叉口也可能出现；若赛道有同样宽黑块，应提高`BSP/Inc/teach_finish.h`的最短终点里程、接近实际一圈长度后再武装，并重新实测，不能保证仅凭8路灰度区分所有同形标记。
- 当前不根据“看见黑线”强行把估计航向拉到地图值，避免将错误匹配当成定位真值。

## 黑字抑制：避障和救援都要验真

仅有`bitmap != 0`不能认为回线成功。在`BSP/Inc/line_guard.h`配置共享的回线验真：

1. 形态必须是1~4个相邻黑点，散点/大片黑字不当窄线；只是候选，不是字符识别。
2. 传感器到地图最近线段距离不超过8cm，候选入线角不超过75度。
3. 低速前进验证，连续至少150ms **且**实际前进至少3cm；静止、倒车、形态/空间门槛失败都会重新计数。
4. 最终车头与地图线段方向差不超过35度，才交回正常循迹。不能停在同一个字上数帧成功。

避障TURN_IN保留原来的运动差速和三段顺序，但需候选连续3拍且至少两路相邻黑点才开始第三段。
第三段动作完成后也必须经过上述滚动验证。TURN_IN连续2.5s找不到候选会退出动作，交给验证/地图返回，不当作已回线。
回线不合地图时不更新匹配锚点。未看到可信线时，即使始终压着黑字，也不会直接清空地图救援的丢线计数。

无地图、定位漂移较大、字体紧贴黑线且方向和宽度相似时，不能保证识别正确；候选可能被保守拒绝而停车。
先保证示教地图可靠、标定正确，再调8cm/35度等门槛，不要为了不停车无限放宽它们。

## 救援怎么触发

地图不接管普通位置PID，但用于否决明显不可信的回线候选。

普通模式下，只有**原避障控制允许循迹**时，连续缺少可信线500ms，并且传感器到地图线段估计距离超过15cm，才触发救援。
避障动作结束但未通过回线验真时允许立即地图返回，不必再等一次500ms。新的障碍请求仍优先。
匹配时优先搜索上次在线位置前后各20段（约100cm），而不是全图无条件选最近点，避免去追另一条平行路或交叉口。

进入救援后锁定目标：

1. 从附近最近线段沿地图前看30cm，再转成轮轴目标（考虑前伸距离），降低垂直扎线的概率；不保证复杂急弯一定能接住。
2. 按目标方位低速原地转向；不是固定转180°。
3. 朝向误差小于15°后低速前进，超过35°则暂停前进、重新转向。
4. 发现合格候选进入滚动验证；时长、位移、地图距离和方向均通过，才交回原循迹。地图到点本身不是成功条件。

限制：最多6s或行驶80cm；偏离超过100cm、到估计目标附近仍看不到线、有效超声波提示近障碍，均停车。
新避障请求优先，会取消地图救援。救援期间主循环的超声波处理超过300ms未更新，也会停车。
超声波无回波**不等于确认无障碍**：细杆、盲区、侧后方仍可能漏检。最近点直线路径不是无碰撞路径规划，实测必须留人看护。

避障TURN_IN新增2.5s超时转地图兜底；退出避障后的验线/返线合计最多6s，不允许靠反复遇到文字一直重置计时。

## 停车响应与终点诊断

- ASCII `0`在DMA接收回调直接锁存，即使命令队列满也生效；下一次10ms TIM1先刹车，再做状态清理，不等OLED/蓝牙回复。
- 急停会丢弃已排队命令，防止旧的`1/3`在停车后自动重放。收到回复后再重新发命令。
- ASCII `2`在学习模式也有TIM1快速停车路径；有效图随后保存，无效图先停再报错。
- 主循环OLED每25ms只刷一行，整屏约200ms，不再一次刷新8行；单行I2C时间和真实中断耗时仍需实测。
- 终点仍需地图进度/空间条件合格，但命中合格FF的本拍就刹车，不再叠加30ms连续全黑等待。
- 已知终点前15cm、正常循迹时，基础目标速度最多20脉冲/10ms，减少冲线和制动滑行；普通循迹仍35，避障运动参数不变。
- **10ms是接收字节后的控制周期，不是手机按键到车轮完全静止的保证**。空口传输、CPU中断负载、轮胎打滑和电机制动仍会影响实车停车距离。屏幕PWM归零但轮速尚大时，是待检查的物理滑行证据。

发`m`或学习失败会附加`END REJxx P... L... N...`：P是最近被拒绝的FF所在进度cm，L是参考圈长，N是被拒绝的FF帧数（不是地图点数）。REJ可按位组合：

| 位 | 原因 |
|---|---|
| `01` | 未到最短行驶距离 |
| `02` | 没有已知圈长，需配置或手动发2 |
| `04` | 不在终点前后30cm窗口 |
| `08` | 没有合格窄线历史 |
| `10` | 非正常前进或地图/避障/救援状态不允许判终点 |

若GS历史里没有FF，说明探头未采到8路全黑，不能只通过缩短软件等待解决。
修改`TEACH_FINISH_EXPECTED_CM`前应实测赛道长度；不能把错误示教的路程或此前丢线后的冲出距离直接当精确圈长。

## 必须标定（BSP/Inc/odom.h）

| 参数 | 初值 | 方法 |
|---|---:|---|
| `ODOM_PULSES_PER_CM` | 68.97 | 48mm轮径、1040脉冲/圈推算；实际走100cm，对照K，新值=旧值×K/100 |
| `ODOM_LEFT_SCALE/RIGHT_SCALE` | 1/1 | 用左右轮各自的实测行程校正；直行不应持续累积航向 |
| `ODOM_TRACK_WIDTH_CM` | 17 | 左右轮接地中心间距；左转5圈，H应为+1800，新值=旧值×实测H/1800 |
| `ODOM_SENSOR_FORWARD_CM` | **17（估值）** | 20cm车长减去轮轴距车尾3cm；仍需实测轮轴到传感器排的纵向距离 |
| `ODOM_RECOVERY_TRIGGER_CM` | 15 | 地图救援距离门槛，不是超声波距离 |
| `ODOM_MATCH_WINDOW` | 20段 | 曲线靠得近时谨慎扩大，可能匹配到另一段赛道 |

改变轮距、轮比例、前伸距离后，旧图会被拒绝加载，需要重新学习。
以最新实车数据为准：车体20x15cm，轮距17cm，轮径48mm，前端灰度排横向长8cm，后轮位于车尾约3cm区域。
此前28mm是口述误记，已恢复68.97脉冲/cm，并将轮距改为17cm、前伸暂估17cm。8cm是排的横向长度，不是前伸距离，也未用于地图横向纠偏。
这些变更会使此前不匹配的地图拒绝加载，须重新发`1`学习、`2`保存。循迹PID、脉冲/10ms目标速度和避障差速累计阈值未改。
每次发车位姿清零；中途停车后若再发`start`，也必须将车放回原起点，**不是断点续跑**。
示教时用车自行低速循迹，不建议推车示教；停车时手推仅用于标定。

## Flash与数据安全

链接脚本保留最后4KB（0x0800F000~0x0800FFFF），程序上限60KB。
两个2KB槽轮换：新地图先写入另一个槽，CRC校验，最后写提交标识。掉电/写失败可加载旧图。
未完成或作废的学习不会擦除旧图。写Flash只在停车时主循环执行，不在TIM1里擦写。
整片擦除、烧录覆盖地图地址仍会丢图。烧录器需要只擦程序所用页，不能承诺任意烧录方式都保留地图。

## 显示与验证

- 第6行：D=估计离线距离cm；M=0无图/1学习/2有图；N=点数；R=0待命/1转向/2前进/3失败/**4低速验线**。
- 第7行：H=累计航向角（左正）；K=累计里程cm。
- 失败会停车，不会自动反复救援。回起点重新start，或者检查参数后重新学习。
- Windows主机测试：`test_odom.c`（需链接`line_guard.c`）覆盖存储和理想返线闭环；`test_line_guard.c`覆盖静止字、短暂黑块、地图不一致和连续位移；`test_avoidance.c`覆盖候选否决与三阶段切换；`test_teach_finish.c`覆盖进度窗口和短终点；`tests/bluetooth_host/test_bluetooth.c`覆盖ASCII、快速停车锁存和队列满时急停。
- 主机测试不能验证轮胎打滑、传感器布局、10ms中断运行时间或真实回线效果，必须先架空确认方向，再低速实跑。

纯编码器位姿存在累计漂移，尤其是原地转弯、碰撞、打滑后。初版不能可靠识别“被人搬动”或定位误差。
若要稳定地跨整圈进行二维返线，建议增加陀螺仪改善角度估计，再配合已知地标校正位置；仅靠这张地图不能保证绝不跑偏。
