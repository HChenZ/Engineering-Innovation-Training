# 超声波避障模块

自动循迹避障小车的**超声波避障**部分。车头左右两侧各装一个探头（**U4 在左侧、
U1 在右侧**），探头向外斜，负责看住左前和右前方；检测到障碍就给出运动建议，
由主循环决定刹车、转向还是继续循迹。

## 一、评分标准怎么算，以及它决定了什么

每轮比赛得分：

```
X =（赛段分 40 + 避障分 40 + 时间分 40 + 停止分 20） ×（1 - n×10%）
```

n 是不合格项数量（尺寸超标、能源不合规各扣 10%；车架非自制、非全自动运行直接不予参赛）。
最后各队按 `80 × (本队得分 / 最高得分)` 归一化排名。

**避障分和循迹分并列最高，各 40 分**，所以这套避障代码值得按下面的规则细节抠。

### 1.1 四个障碍物（位置每轮由裁判随机摆放，在循迹线的任意一侧）

| 编号 | 名称 | 尺寸（长×宽×高 mm） | 赛段 |
| --- | --- | --- | --- |
| 1 | 敦煌莫高窟 | 150 × 100 × 150 | 第 1 段 |
| 2 | 新疆阿凡提 | **60 × 60 × 150** | 第 2 段 |
| 3 | 德黑兰自由纪念塔 | 120 × 70 × 150 | 第 3 段 |
| 4 | 伊斯坦布尔圣菲索亚大教堂（内含 1kg 铁块） | 110 × 100 × 170 | 第 4 段 |

**障碍物 2 只有 60mm 宽，是这套方案最大的风险点。** 两个探头向外斜装，
正前方本来就有盲区，一个 6cm 宽的柱子正好落在盲区里就漏掉了。
必须按"最小那个障碍物"来做实测，不能拿大箱子试通了就算过。

### 1.2 两条会影响代码设计的规则

**① "小车应自动按循迹线前进，一旦逆行，本轮比赛结束。"**
后退有可能被判成逆行，一旦判罚整轮作废，**代价远大于收益**。
所以 `avoid.h` 里的 `AVOID_ALLOW_BACK` 默认是 `0`（禁止后退），
需要逃生时一律改成原地转向——原地转不产生倒车位移，不构成逆行。
只有确认裁判认可后退动作，才建议改成 `1`。

**② "除必要避障外，禁止脱离循迹线；若发生非避障脱离，则脱离期间所经赛段不计分。"**
避障导致的短暂脱线是允许的，但必须能自己回到线上。
所以避障动作要**干脆利落**：刹车 + 转向加起来约 0.5 秒，转完立刻交还给寻迹，
让寻迹逻辑尽快把车拉回黑线。

### 1.3 一个容易踩的坑：赛段完成标识

赛道上有 4 个"赛段完成标识"，尺寸约 120×50×120mm，就摆在线旁边，
用来判断小车有没有跑完这一段。**超声波很可能把它当障碍物**，
于是小车莫名其妙地绕一下——这属于"非避障脱离"，该赛段直接不计分。

对策：`AVOID_STOP_CM` 不要设得过大，并且**一定要在真实赛道上实测**，
确认经过标识物时不会误触发。这是调参时最该盯的一件事。

## 二、新增文件

| `Inc/hcsr04.h` / `Src/hcsr04.c` | HC-SR04 驱动：触发、计时、换算、超时处理 |
| `Inc/avoid.h` / `Src/avoid.c` | 避障逻辑：轮流采样探头，输出运动建议 |

`BSP/Inc` 也已经在 include 路径里。

## 三、硬件与引脚

底板预留 3 个 4P 超声波插座（`+5V / TRIG / ECHO / GND`）：

| 插座 | 位置 | TRIG | ECHO | 本项目 |
| --- | --- | --- | --- | --- |
| U1 | 车头**右侧** | PA8 | PA9 | 使用 |
| U2 | 车头正中 | PA10 | PA11 | 可选（见下） |
| U4 | 车头**左侧** | PA4 | PA5 | 使用 |

### 三个必须注意的点

**1. PA5 不是 5V 容忍引脚。** U4 的 ECHO 接在 PA5 上，而 PA5 是 TTa 类型，
只能承受 3.3V；插座第 1 脚供的却是 +5V，宽电压版模块在 5V 下 ECHO 输出也是 5V，
直接灌进去会损坏芯片。两个办法：把 U4 那路模块改成 **3.3V 供电**
（这款模块支持 3-5.5V），或在 ECHO 与 PA5 之间加分压（1k + 2k）。
PA9、PA11 都是 5V 容忍脚（FT），另外两路不受影响。

**2. 正前方盲区。** 波束角 ±15°（典型），两个探头各向外斜 30°，
中间就留下约 30° 的空档。建议外斜角控制在 **20~30° 以内**，
让两个探测锥在前方有一段重叠；拿 60mm 宽的障碍物对着车头正中试，
测得到才算过关。

如果测不到，**把中间的 U2 探头插上**，再把 `avoid.h` 里的
`AVOID_USE_CENTER` 从 `0` 改成 `1`。硬件插座和驱动都是现成的，
而且加了中间探头后，正前方距离会取三路里的最小值，
即使中间探头忘了插，左右两路依然兜底，不会哑火。

**3. 安装高度。** 四个障碍物高度都在 150~170mm，探头离地 5~10cm 都落在
有效范围内。注意别装得太高，否则低矮物体从波束下方溜过去；
也别太低，地面反光会干扰。装好后拿实际障碍物在 30cm 外验证一遍。

## 四、接进主程序

只需要在 `Core/Src/main.c` 的三个 USER CODE 区里各加几行：

```c
/* USER CODE BEGIN Includes */
#include "avoid.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
Avoid_Init();
/* USER CODE END 2 */

/* USER CODE BEGIN 3 */
switch (Avoid_Update())
{
case AVOID_FOLLOW: /* 交还给你们的寻迹函数 */
    break;

case AVOID_SLOW: /* 循迹，但速度降到一半 */
    break;

case AVOID_BRAKE: /* 立即刹车（短接制动） */
    Motor_BrakeAll();
    break;

case AVOID_TURN_LEFT: /* 原地左转 */
    Motor_SetSpeed(MOTOR_LEFT, MOTOR_START, -40);
    Motor_SetSpeed(MOTOR_RIGHT, MOTOR_START, 40);
    break;

case AVOID_TURN_RIGHT: /* 原地右转 */
    Motor_SetSpeed(MOTOR_LEFT, MOTOR_START, 40);
    Motor_SetSpeed(MOTOR_RIGHT, MOTOR_START, -40);
    break;

case AVOID_BACK: /* 后退（默认被 AVOID_ALLOW_BACK 关掉，不会走到这里） */
    Motor_SetSpeed(MOTOR_LEFT, MOTOR_START, -40);
    Motor_SetSpeed(MOTOR_RIGHT, MOTOR_START, -40);
    break;
}
/* USER CODE END 3 */
```

避障模块**不直接控制电机**，只返回"建议动作"，这样寻迹和避障互不干扰，
也方便单独调试。

## 五、动作是怎么决策出来的

```
FOLLOW  正常循迹（持续轮流测左右两路）
  |  前方距离 <= AVOID_STOP_CM
  v
BRAKE   先刹车停稳（AVOID_BRAKE_MS = 120ms）
  |  停稳后用最新读数判断
  |-- 前方已通畅 -> 回到 FOLLOW
  '-- 仍然很近   -> TURN：原地转向更空的一侧
  v
TURN    保持 AVOID_TURN_MS，然后回到判断
```

**为什么必须先刹车再转向。** 带着速度原地转，车身角会甩出去，
很容易蹭到本来还有十几厘米的障碍物；规则是"任何部件接触即失败"，
先停稳再转等于多买了半秒余量。

**为什么默认不后退。** 见 1.2 的逆行风险。

**为什么无回波当"通畅"。** 量程内没东西时 ECHO 没有脉冲，此时报 -1，
逻辑上按"很远"处理。

## 六、参数

都在 `avoid.h` 顶部，按实车调整：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `AVOID_USE_CENTER` | 0 | 是否启用中间探头；正前方测不到 60mm 障碍就改成 1 |
| `AVOID_ALLOW_BACK` | 0 | 是否允许后退；默认禁止，避免被判逆行 |
| `AVOID_STOP_CM` | 25 | 小于此距离触发避障（含刹车） |
| `AVOID_SLOW_CM` | 50 | 小于此距离减速但继续循迹 |
| `AVOID_SAMPLE_MS` | 40 | 采样周期，两路轮流则单路约 80ms 更新一次 |
| `AVOID_BRAKE_MS` | 120 | 刹车保持时间 |
| `AVOID_TURN_MS` | 350 | 转向保持时间，**最需要调的一个** |
| `AVOID_BACK_MS` | 250 | 后退保持时间（`AVOID_ALLOW_BACK=1` 时才生效） |
| `HCSR04_TIMEOUT_US` | 8000 | 测距超时，约 1.37m，同时决定单次测量最坏阻塞时间 |

**`AVOID_STOP_CM` 定多大要权衡两件事**：设小了来不及刹车（采样单路 80ms
才更新一次，车速快的话已经走出去几十厘米）；设大了又容易被赛段标识物
误触发，白丢赛段分。先用 25cm 起步，在真车上两头试。

## 七、实现说明

**为什么不用定时器测距。** TIM2 给了电机 PWM、TIM3/TIM4 给了两路编码器，都占满了。
所以用 Cortex-M3 自带的 **DWT 周期计数器**做微秒计时（`DWT->CYCCNT`），
不占用任何外设，也不需要在 CubeMX 里加配置。

**单次测量的阻塞上限。** 等回波上升沿和量脉宽**共用同一个超时预算**，
所以最坏阻塞就等于 `HCSR04_TIMEOUT_US`（8ms）。
（如果两个循环各用一份超时，最坏会翻倍到 16ms，寻迹会明显发顿——这里踩过。）

**防漏报。** 盲区（2-4cm）内的读数是随机值，如果当成"没测到"，
贴脸的障碍就会被判成通畅。所以回波短于 116us（约 2cm）时按 2cm 上报，
宁可误报，不要漏报。

**测量间隔。** 手册建议两次测量间隔 ≥200ms 以保证远距离精度，
厂家示例用 30+100ms。避障只关心一两米内，这里用 `AVOID_SAMPLE_MS`
（40ms，两路轮流则单路 80ms）换响应速度。

## 八、调试建议

把这几行加到主循环里，就能从串口或 OLED 看到实时距离：

```c
int16_t d_front = Avoid_GetFrontCm();
int16_t d_left  = Avoid_GetLeftCm();
int16_t d_right = Avoid_GetRightCm();
```

`-1` 表示该路量程内没有障碍。按这个顺序试：

1. 拿**最小的那个障碍物（60×60×150mm）**，从车头正前方慢慢靠近，
   看能不能读到、几厘米开始能读到
2. 换成从**左前方、右前方**靠近，看两侧探头是否灵敏
3. 把 4 个实际障碍物依次放在线旁边，让车慢速通过，确认都绕开了
4. 用赛段标识物（120×50×120mm）摆在线旁，确认车**不会**误触发
5. 最后才提速，验证 `AVOID_STOP_CM` 在最快的速度下还来得及

## 九、比赛前检查清单

- [ ] U4 那一路的 ECHO 电压实测过，确认 PA5 没被灌 5V
- [ ] 用 60mm 宽的最小障碍物测过正前方，确认没有盲区
      （测不到就把 `AVOID_USE_CENTER` 改成 1 并插上 U2 探头）
- [ ] 赛段标识物摆在线旁时不会误触发避障
- [ ] 避障全程没有碰到障碍物（连蹭都不行），连续跑几轮验证
- [ ] 避障结束后小车能自己回到黑线上
- [ ] 探头安装高度匹配实际障碍物
- [ ] 蓝牙模块比赛时断开或程序里不启用（规则不允许任何遥控/远程控制）
- [ ] 整车尺寸 ≤ 250×200×200mm，车架自制，只用一个车载电源
- [ ] 终点停车：过线后要能停住且车尾不越线（停止分 20 分，由寻迹那边负责）
